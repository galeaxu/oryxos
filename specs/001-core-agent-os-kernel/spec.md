## 范围说明（Scope Framing）

本规格覆盖 **Agent OS 运行时内核**的最小完备集：业务方配置一个 Agent、与它对话、它调用模型与工具完成任务、并能被外部系统通过接口调用。核心阶段交付的是**地基**（运行时内核），不是治理能力完备的企业级 Agent OS；多 Channel、Provider 故障切换、向量检索、Tool Policy、完整容器隔离、认证鉴权、多租户等治理与重型能力明确排除在本规格之外。

规格以 `docs/DemandAnalysis.md` 为需求来源，以 `.specify/memory/constitution.md` v2.0.1 为不可违背约束。若两者冲突，以宪法为准。

> **确定性口径说明**：需求文档写作于 Profile 单文件配置模型下；宪法 v2.0.0/v2.0.1 已将 Agent 定义模型重定义为「一个目录 = 一个 Agent，Skill 以本地相对软连接绑定」。本规格遵循宪法的最新定义，需求文档中与此冲突的表述（例如在 `AGENT.md` frontmatter 里用 `skills:` 列表引用 Skill、Skill 与 Tool 混为一谈）不再作为验收依据。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 对接 LLM：让 Agent 能说上话 (Priority: P1)

业务方在自己的机器上初始化工作区，填好一个模型服务的访问凭据，选中一个模型，就能与一个 Agent 开始一轮对话并获得符合人设的回复。换模型时只改配置，不动任何代码。

**Why this priority**: 这是整条链路的第一环。没有可用的模型接入，ReAct、记忆、工具、接口都无从谈起。它单独交付即可证明「企业自有环境内跑通一次模型对话」这一核心价值。

**Independent Test**: 在一个干净目录初始化工作区、配置一个可用模型凭据后，发起一轮对话并收到非空回复；把配置里的模型换成另一家并重复对话，两次都成功，且过程中未修改任何代码。

**Acceptance Scenarios**:

1. **Given** 一个干净目录且尚未初始化，**When** 用户执行工作区初始化，**Then** 目录下形成完整的工作区结构（Agent 定义区、配置区、会话区、公共技能区、日志区、长期记忆文件与运行所需的本地数据文件），并生成一份可直接使用的默认 Agent。
2. **Given** 工作区已初始化且已注入模型凭据，**When** 用户发起一轮对话，**Then** Agent 在合理时间内返回与设定人设一致的回复。
3. **Given** 已配置两家不同模型供应商，**When** 用户仅切换配置中的供应商名称后重新对话，**Then** 对话成功且无需修改或重新编译任何代码。
4. **Given** 配置中引用了未注册的供应商名称，**When** 用户发起对话，**Then** 系统明确报错并指出是哪个 Agent 配置的哪个字段无效，而不是静默降级到其他供应商。

### User Story 2 - ReAct 循环：让 Agent 能自己动手 (Priority: P2)

用户提出一个需要外部信息或多步操作的任务，Agent 自行判断该调用哪个工具、执行它、看到结果后继续判断，最终给出综合答复。整个过程用户只看到最后结果，但每一步都可追溯。

**Why this priority**: ReAct 是 Agent 区别于普通对话机器人的核心。US-1 只证明「能说话」，US-2 才证明「能干活」，且它依赖 US-1 已具备模型接入。

**Independent Test**: 向 Agent 提出一个必须借助工具才能回答的问题（例如查询外部信息后据此给出建议），观察它完成工具调用并给出包含工具结果的答复；对话结束后可查到完整的「思考—调用—回填」链路的留痕。

**Acceptance Scenarios**:

1. **Given** Agent 已配置可用工具，**When** 用户提出需要外部信息的问题，**Then** Agent 调用相应工具并以工具结果为依据作答，而非凭空生成。
2. **Given** 一次用户请求需要多次工具调用，**When** 执行过程结束，**Then** 系统按顺序完成全部调用并把每次结果回填给模型，最终返回综合答复。
3. **Given** 模型持续要求调用工具而不给最终答复，**When** 迭代次数达到配置的上限，**Then** 系统强制结束并返回可理解的终止说明，不无限循环。
4. **Given** 本次请求配置了不同的迭代上限，**When** 执行同样任务，**Then** 上限按该 Agent 的配置生效，而非固定值。
5. **Given** 单次工具执行失败，**When** 失败可重试，**Then** 系统按重试策略再次执行；重试次数耗尽后把失败原因回填给模型，由模型决定后续动作。

### User Story 3 - Memory 记忆：让 Agent 记得住 (Priority: P3)

用户在一次对话里告诉 Agent 自己的偏好或项目背景，之后开启全新对话，Agent 仍能引用这些信息，无需用户重复说明。同时，进行中的对话在服务重启后可继续。

**Why this priority**: 「记得住」是 Agent OS 区别于一次性问答的核心体验。它依赖 US-2 的循环能力才能被自然触发，但与 US-4 相互独立，可并行推进。

**Independent Test**: 第一次对话中告知偏好并要求记住，结束后开启全新对话直接提问相关事项，Agent 能在不重复告知的情况下引用该偏好作答；另做一次重启服务后继续原会话验证上下文未丢失。

**Acceptance Scenarios**:

1. **Given** 用户告知了一个需要长期记住的偏好，**When** Agent 判断值得保留，**Then** 该内容被写入长期记忆并在后续对话中可被检索引用。
2. **Given** 长期记忆已存在内容，**When** Agent 开始新一轮对话，**Then** 已保存的长期记忆在对话中可被使用，无需用户重复告知。
3. **Given** 进行中的会话，**When** 服务重启后用户继续该会话，**Then** 历史对话上下文可恢复，对话可继续。
4. **Given** 用户追问与长期记忆相关的关键词，**When** Agent 检索长期记忆，**Then** 返回与该关键词相关的内容，而非全量倾倒。
5. **Given** 长期记忆内容超出设定容量，**When** 继续写入，**Then** 系统按既定策略保留最近内容并保持可用，不因超限而报错中断。

### User Story 4 - Plugin Tool：让业务方零代码扩展能力 (Priority: P3)

业务方想在 Agent 上新增一项业务能力，最优先的方式是只写一份描述意图的说明文档、复用社区现成的工具服务，全程不写代码；当社区没有现成服务时，才用任意语言自建一个工具服务接入；只有在需要深度集成企业自有 Java 服务时，才写少量 Java 代码。

**Why this priority**: 这是「业务方不写 Agent 后端代码」承诺的兑现途径，也是 OryxOS 与框架类产品的差异点。它与 US-3 相互独立，可并行推进，均依赖 US-2。

**Independent Test**: 用零代码方式接入一个社区工具服务并完成一次实际调用；另用少量 Java 代码方式接入一个自有能力并完成一次实际调用；两种方式注册后都能被列出来并被 Agent 在一次任务中使用。

**Acceptance Scenarios**:

1. **Given** 业务方只写了一份意图说明文档并声明了要复用的外部工具服务，**When** 用户提出该文档描述范围内的任务，**Then** Agent 能理解意图并调用外部工具服务完成任务，全程未写代码。
2. **Given** 业务方用任意语言实现了一个符合标准协议的工具服务并在配置中声明，**When** 系统启动，**Then** 该服务暴露的工具被注册并可在任务中被调用。
3. **Given** 业务方用一个带标注的 Java 方法暴露了一项自有能力，**When** 系统启动，**Then** 该能力被自动注册并可在任务中被调用。
4. **Given** 多个来源的工具都已注册，**When** 查询可用工具，**Then** 能列出全部工具及其来源，且同一 Agent 只看到其被允许的那一部分。
5. **Given** 某 Agent 只被授予部分工具，**When** 它尝试调用未授予的工具，**Then** 调用被拒绝，且不影响其他 Agent 的正常使用。

### User Story 5 - Web Service：让业务系统把 Agent 接进去 (Priority: P4)

业务系统通过标准接口调用 OryxOS：创建会话、发送消息拿到答复、查询历史、归档会话；也能无状态地一次性调用某个 Agent；还能查询已配置的 Agent、可用工具、长期记忆与系统健康状态。整个过程不关心内部实现。

**Why this priority**: 这是企业把 AI 能力嵌入已有产品的唯一通道，也是 OryxOS 区别于个人助手项目的关键。它需要前四项能力都已具备，因此排在最后。

**Independent Test**: 用一个通用接口调用方，依次完成健康检查、创建会话、发送消息、查询历史、归档会话、无状态调用 Agent、查询 Agent 列表、工具列表与长期记忆，整条链路返回结果正确。

**Acceptance Scenarios**:

1. **Given** 服务已启动，**When** 外部系统请求健康检查与系统信息，**Then** 返回可用状态、版本、已加载 Agent 数量与已注册工具数量。
2. **Given** 外部系统新建一个会话并发送一条消息，**When** 请求正常完成，**Then** 返回 Agent 的最终答复，且该会话后续可继续发送消息并保持上下文。
3. **Given** 会话已有多轮对话，**When** 外部系统查询该会话历史，**Then** 按时间顺序返回历史消息及其中的工具调用记录。
4. **Given** 外部系统归档一个会话，**When** 归档完成后再次查询该会话，**Then** 该会话标记为已归档且不再是活跃状态。
5. **Given** 外部系统需要一次性调用某个 Agent 且不需要保持上下文，**When** 发起无状态调用，**Then** 返回本次答复且不产生新会话。
6. **Given** 外部系统查询 Agent 列表、工具列表与长期记忆，**When** 请求完成，**Then** 分别返回当前已配置的 Agent、已注册工具与已保存的长期记忆内容。
7. **Given** 外部系统发送超长消息或调用超时，**When** 命中上限，**Then** 系统返回明确的错误响应，说明是消息过长、请求无效还是处理超时。

### Edge Cases

- **凭据缺失**：配置引用的模型凭据缺失或格式非法时，系统必须在启动或首次调用时清晰报错并指出缺失项，不得静默降级或让请求挂起。
- **工具越界访问**：工具尝试访问允许范围之外的文件路径、执行白名单外的命令、访问白名单外的网络地址时，必须被拒绝并给出明确原因，不得部分执行。
- **软连接越界**（遵循宪法原则 VI）：Agent 的技能绑定若为绝对路径软连接、链式越界或指向公共技能目录之外，必须在加载或绑定时拒绝；任何经由软连接的访问都必须以解析后的真实路径判定是否仍在允许范围内。
- **技能引用悬空**：某个被 Agent 引用的公共技能被删除或移动后，启动与操作时须识别出悬空引用并明确报错，不得静默忽略；删除仍被引用的公共技能时默认拒绝并列出引用方。
- **技能命名不一致**：Agent 本地绑定的名称与其指向的公共技能声明名称不一致时，须识别为无效绑定。
- **迭代失控**：模型始终不给最终答复时，必须在上限处终止，不得无限循环或耗尽资源。
- **上下文超限**：对话历史超出模型上下文上限时，按既定策略保留近期内容使对话可继续，不得因超限直接失败。
- **并发同会话写入**：同一会话被并发追加消息时，历史消息不得丢失或错乱。
- **服务重启中的会话**：服务重启时正在进行的会话，重启后须可恢复或给出明确状态，不得出现半写入的损坏数据。
- **空/超长输入**：空消息、超长消息、非法请求体都必须返回明确错误，不得导致进程异常。
- **外部工具服务不可用**：外部工具服务启动失败或中途断开时，须标明该工具不可用，且其余工具与会话不受影响。

## Requirements *(mandatory)*

### Functional Requirements

**Agent 定义与工作区**

- **FR-001**: 系统 MUST 支持一次性初始化工作区，形成完整的目录结构（Agent 定义区、配置区、会话区、公共技能区、日志区、长期记忆文件、本地数据文件）与一份可直接使用的默认 Agent。
- **FR-002**: 一个 Agent MUST 完全由一个目录定义：该目录内的一份主说明文件（含运行配置元数据与任务指令正文）定义其身份、模型选择、可见能力与任务指令；业务方定义 Agent MUST NOT 需要编写任何代码。
- **FR-003**: 系统 MUST 支持在同一实例内并存多个 Agent，每个 Agent 相互独立、互不干扰。
- **FR-004**: 用户对 Agent 定义的修改 MUST 在下次对话时生效，MUST NOT 需要重新编译或重启进程。
- **FR-005**: 当 Agent 定义缺失必填项、格式非法或引用了不存在的资源时，系统 MUST 明确报错并指出是哪个 Agent 的哪个字段，MUST NOT 静默使用默认值或部分加载。

**能力一：模型接入**

- **FR-006**: 系统 MUST 通过统一的模型接入抽象对接多家模型服务，Agent MUST NOT 感知具体调用的是哪一家。
- **FR-007**: 用户 MUST 能仅通过修改配置在多家模型服务之间切换，MUST NOT 需要改动代码。
- **FR-008**: 系统 MUST 对每一家已接入的模型维护明确的名称到连接实例的对应关系；当多个模型并存时，请求 MUST 按配置名称路由到唯一确定的模型。
- **FR-009**: 每一次模型调用 MUST 记录所用供应商、模型、token 用量与耗时。
- **FR-010**: 核心阶段，模型服务不可用时系统 MUST 直接向调用方返回明确错误；MUST NOT 静默切换到其他模型。

**能力二：Reason-Act 循环**

- **FR-011**: 系统 MUST 自行掌控「思考—调用工具—回填结果—再思考」的完整循环，循环的迭代上限、终止条件与上下文裁剪策略 MUST 可配置。
- **FR-012**: 循环 MUST 在模型不再请求工具时返回最终答复，在模型持续请求工具时于达到迭代上限后强制终止。
- **FR-013**: 每次迭代中模型的响应与工具的结果 MUST 被追加到会话历史，使完整调用链可追溯。
- **FR-014**: 迭代上限 MUST 支持按单个 Agent 覆盖默认值。
- **FR-015**: 工具执行失败时，系统 MUST 依据该工具声明的可重试性决定是否重试，并把最终失败原因回填给模型。
- **FR-016**: 单次请求内的多次工具调用 MUST 按顺序执行；核心阶段 MUST NOT 并行执行工具。

**能力三：记忆**

- **FR-017**: 会话历史 MUST 持久化，服务重启后进行中的会话 MUST 可恢复。
- **FR-018**: 系统 MUST 提供跨对话保留的长期记忆，以人类可读的文件形式存放于工作区，MUST NOT 在核心阶段依赖向量库。
- **FR-019**: Agent MUST 能主动把值得长期保留的内容写入长期记忆，MUST NOT 由系统替代 Agent 决定写入内容。
- **FR-020**: Agent MUST 能按关键词检索长期记忆并取得相关内容。
- **FR-021**: 长期记忆内容 MUST 在对话中可被使用，且写入后对后续对话立即可见。
- **FR-022**: 长期记忆超出设定容量时 MUST 按既定策略保留近期内容并保持可用，MUST NOT 因超限导致写入失败或数据损坏。
- **FR-023**: 会话上下文超出模型可处理上限时 MUST 按既定策略保留近期对话使会话可继续。
- **FR-024**: 用户偏好（只读的初始设定文件）与 Agent 自主写入的长期记忆 MUST 是两份不同的内容，前者 MUST NOT 被 Agent 写入流程修改。

**能力四：工具体系**

- **FR-025**: 系统 MUST 统一以「名称、说明、输入结构、执行结果」这组信息描述每一个工具，循环逻辑 MUST NOT 感知工具的实现来源。
- **FR-026**: 系统 MUST 内置基础工具集：文件读取、文件写入、目录列举、命令执行、HTTP 请求（含 GET 与 POST）。
- **FR-027**: 系统 MUST 支持三档外部工具接入：① 只写意图说明文档并复用现成外部工具服务（零代码，**MUST 作为首选推荐方式**）；② 用任意语言实现符合标准协议的外部工具服务并接入；③ 用带标注的 Java 方法暴露能力并在启动时自动注册。
- **FR-028**: 当仅用第二档或第三档即能满足需求时，方案 MUST 说明为何第一档不可行。
- **FR-029**: 系统 MUST 能连接外部工具服务并将其暴露的工具注册进工具集合，配置 MUST 在专门的工作区文件中声明。
- **FR-030**: 每一个 Agent MUST 只看到并被允许调用其被授予的那部分工具；调用未授予的工具 MUST 被拒绝。
- **FR-031**: 技能说明 MUST 作为上下文资源参与对话，MUST NOT 被当作可执行工具注册；系统 MUST NOT 提供「使用技能」这类执行入口，也 MUST NOT 在每轮对话中预载技能正文、参考文件或脚本。
- **FR-032**: 系统 MUST 在每轮对话中从 Agent 本地技能绑定重新获取当前可用技能的元信息（名称、说明、可读取位置），并 MUST NOT 缓存。
- **FR-033**: 公共技能 MUST 集中存放在公共技能区；某 Agent 可见的技能 MUST 仅由其本地绑定关系表达，MUST NOT 再以配置元数据字段或第二份索引表达同一关系。
- **FR-034**: 技能的创建、导入、更新、删除，Agent 的绑定、解绑、归档、删除以及启动恢复 MUST 执行一致性检查，识别悬空引用、越界绑定、目标非法、名称不一致与过期引用。
- **FR-035**: 删除仍被 Agent 引用的公共技能时，系统 MUST 默认拒绝并列出引用方。

**能力五：对外接口**

- **FR-036**: 系统 MUST 通过标准 REST 接口暴露会话管理、Agent 调用、信息查询与系统状态四类能力。
- **FR-037**: 核心阶段 MUST 提供不少于以下十项操作：创建会话、向会话发送消息、查询会话历史、归档会话、无状态调用 Agent、列出 Agent、查询长期记忆、列出已注册工具、健康检查、系统信息。
- **FR-038**: 查询会话历史 MUST 返回按时间顺序的消息及其中的工具调用记录，并有条数上限。
- **FR-039**: 无状态调用 Agent MUST 不创建会话且不保留上下文。
- **FR-040**: 系统 MUST 对非法请求、越界输入与处理超时返回明确的错误响应（区分请求无效、资源不存在、服务不可用、处理超时）。
- **FR-041**: 核心阶段 MUST NOT 要求认证鉴权、流式响应或长连接推送。

**审计与安全（宪法原则 V、VI，Day One 强制）**

- **FR-042**: 每一次工具调用 MUST 写入持久化的审计记录（会话、Agent、工具名、参数、状态、起止时间、结果或错误），MUST NOT 仅写日志。
- **FR-043**: 每一次模型调用 MUST 写入持久化的审计记录（会话、供应商、模型、token 用量、耗时、状态、起止时间）。
- **FR-044**: 审计写入 MUST 在核心阶段即生效；审计查询与报表能力 MAY 延后。
- **FR-045**: 工具执行 MUST 经过白名单校验：文件访问按路径白名单、命令执行按命令白名单、网络访问按域名白名单；校验不通过 MUST 拒绝执行并说明原因。
- **FR-046**: 任何经由软连接的文件访问 MUST 以解析后的真实路径判定是否位于允许范围内；对尚不存在的目标 MUST 以其最近存在的父目录的真实路径判定；字符串规范化比较 MUST NOT 被视为充分的安全判定。
- **FR-047**: 敏感凭据 MUST 通过环境变量或外部密钥方式注入，MUST NOT 明文出现在代码、配置、日志或提交历史中。
- **FR-048**: 系统 MUST NOT 依赖 JVM 已废弃的运行时安全机制实现隔离。

**运行与运维**

- **FR-049**: 系统 MUST 提供三种运行方式：交互式对话、对外接口服务、常驻守护模式；三者 MUST 共享同一份 Agent 配置与会话存储。
- **FR-050**: 系统 MUST 提供命令行入口，覆盖工作区初始化、状态查看、对话、启动接口服务、启动守护进程、Agent 的增删查列、供应商列表、工具列表、会话列表。
- **FR-051**: 系统 MUST 输出结构化运行日志，MUST NOT 以非结构化标准输出作为运行日志来源。
- **FR-052**: 系统 MUST 在任何启动阶段对必填配置做校验，缺失或非法时 MUST 给出清晰错误并终止启动，MUST NOT 静默以不完整配置运行。
- **FR-053**: 数据表结构的演进 MUST NOT 依赖运行时的自动建表推导完成，MUST 通过显式迁移脚本管理。

### Key Entities *(include if feature involves data)*

- **Agent 定义**：定义一个 Agent 的全部信息——名称、说明、身份与人设指令、模型选择、可见工具集合、可见技能绑定、引导上下文引用、运行参数（迭代上限、历史保留轮数）。以工作区内的一个目录为单位存在。
- **公共技能**：可复用的上下文资源，含名称、说明与正文，另可附带参考文件与脚本；与 Agent 之间通过 Agent 本地的相对软连接建立可见关系，二者相互独立存放。
- **工作区**：一个 OryxOS 实例的根目录，容纳 Agent 定义、公共技能、长期记忆、会话数据、日志与本地数据库。
- **模型接入配置**：一个可用模型服务的连接信息，含名称、模型标识与连接参数；Agent 通过名称引用它。
- **会话**：一次对话的上下文容器，含标识、所属 Agent、来源渠道、用户标识、消息序列、状态与时间戳；跨重启可恢复。
- **消息**：会话中的一条记录，含角色、内容、时间戳与其中的工具调用信息。
- **长期记忆**：以人类可读文件形式保存、跨会话复用的内容，可被追加与按关键词检索。
- **工具**：可被 Agent 调用的能力，含名称、说明、输入结构与执行结果；来源可为内置、外部协议服务或本地代码。
- **工具调用审计记录**：一次工具执行的留痕，含会话、Agent、工具名、参数、状态、起止时间、结果或错误。
- **模型调用审计记录**：一次模型调用的留痕，含会话、供应商、模型、token 用量、耗时、状态与起止时间。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新用户在 10 分钟内可完成「初始化工作区 + 配置模型凭据 + 发起第一轮对话」并收到有效回复。
- **SC-002**: 从桌面端进行一次「需要两次及以上工具调用」的任务，全程用户只需发起一次请求，Agent 在无人干预下完成并给出综合答复。
- **SC-003**: 用户在首次对话告知的偏好，在同一时段内的第二次全新对话中被正确引用，引用成功率 100%（5 次验证全部命中）。
- **SC-004**: 业务方以零代码方式上线的工具场景，从写下意图说明到完成一次真实调用，耗时不超过 30 分钟，且全程未新增或修改任何代码。
- **SC-005**: 外部系统仅凭接口文档即可完成「建会话 → 发消息 → 查历史 → 归档 → 无状态调用」全链路，一次跑通，无需阅读内部实现。
- **SC-006**: 服务重启后，重启前进行中的会话可继续对话，历史消息无丢失（验证 5 次全部成功）。
- **SC-007**: 每一次工具调用与模型调用，均可从持久化审计记录中完整还原（抽取 20 次调用的审计完整性达到 100%）。
- **SC-008**: 所有越界访问尝试（越界文件路径、白名单外命令、白名单外域名、越界软连接）在验证中被 100% 拒绝，且无一次造成部分执行。
- **SC-009**: 单实例在核心阶段可稳定承载不少于 10 个 Agent 并存与不少于 100 个并发会话，会话创建在 95% 情况下于 200 毫秒内完成。
- **SC-010**: 核心阶段全部五个能力各有一个可现场演示的端到端场景，五个场景均可在一次演示中连续跑通。

## Assumptions

- **配置模型以宪法为准**：Agent 由「一个目录」定义，公共技能以 Agent 本地相对软连接绑定；需求文档中「Profile 单 YAML 文件 + frontmatter skills 列表」的旧表述不适用，凡与之冲突处以宪法 v2.0.1 为准。
- **运行时基线**：运行环境为 JDK 21 及以上；以单体多模块方式构建并产出单一可执行包；部署于企业自有环境（服务器 / 虚拟机 / 容器），数据不出域。
- **同步执行模型**：核心阶段全程同步处理，并发由运行时自身的轻量线程机制承载，不引入异步编程模型；流式响应不属于本规格。
- **持久化选型**：默认使用嵌入式数据库，表结构由显式迁移脚本管理；数据库可替换性在部署选项层面考虑，不作为本规格的验收项。
- **长期记忆形态**：以文件形式保存 + 关键词检索，不引入向量检索；语义检索、自动抽取事实、任务过程记忆均属后续阶段。
- **模型凭据可用**：假定用户具备至少一家模型服务的可用凭据，并能通过环境变量注入。
- **不做的范围**：多消息渠道接入（企业微信 / 飞书 / 钉钉 / Slack / 邮件）、模型故障自动切换与动态路由、工具使用策略与按需加载、容器级隔离、认证鉴权与多租户、Web 管理界面、可观测性指标看板、集群化部署，均不在本规格范围内。
- **零代码优先**：外部工具接入默认先评估第一档（意图说明 + 复用现成服务）；只有在其不可行时才使用第二档或第三档，且须在方案中说明理由。
- **演示优先于完美**：核心阶段的成功标准是端到端可演示，性能指标为方向性目标，未达标不阻断交付，但须记录并留待后续优化。
